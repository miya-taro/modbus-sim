# 要求仕様書：Modbus TCP / RTU マルチ模擬ツール（シミュレータ）

## 1. プロジェクト全体の概要
- **システムの目的・背景**: 
  Modbus通信を行う上位システム（マスタ）の開発やテストにおいて、実機（スレーブ）がない状態でも通信疎通およびデータハンドリングの検証を可能にするため、ローカル環境で動作する軽量かつモダンなUIを持つModbusシミュレータを構築する。
- **ターゲットユーザー**: 自分で通信検証やデバッグを行う開発者（俺氏）
- **主要な機能一覧**:
  1. Modbus TCP および Modbus RTU スレーブの切り替え、非同期起動・停止機能
  2. 主要レジスタ（Holding Register等）の状態可視化（UI表示）機能
  3. UIからのレジスタ値の動的変更機能
  4. 外部（マスタ）からのデータ読み書き検知およびログ出力機能
- **システムの全体的な流れ**:
  アプリ起動 ➔ 通信モード（TCP / RTU）の選択 ➔ 各種通信パラメータの設定 ➔ サーバー開始ボタン押下 ➔ 非同期で指定されたModbusサーバーがバックグラウンド起動 ➔ 外部マスタからの要求を処理しいつつ、画面上のデータ表示をリアルタイム更新。

## 2. 詳細機能要件

### F01: 通信制御機能
- **通信プロトコル**: Modbus TCP および Modbus RTU（**同時起動可能**）
- **ロール**: スレーブ（サーバー）
- **TCP設定パラメータ**:
  - IPアドレス（デフォルト: `127.0.0.1`）
  - ポート番号（デフォルト: `5020`）
- **RTU設定パラメータ**:
  - シリアルポート（例: `COM1`, `/dev/ttyUSB0` 等、テキスト入力または利用可能ポートのドロップダウン選択）
  - ボーレート（`9600`, `19200`, `38400`, `115200` 等から選択、デフォルト: `9600`）
  - パリティ（`None`, `Even`, `Odd` から選択、デフォルト: `Even`）
  - データビット（固定: `8`）
  - ストップビット（固定: `1`）
- **データストア割当**:
  - Holding Register (保持レジスタ): アドレス `0` 〜 `65535` (計65536面、初期値 `0`)

### F02: 画面UI・データ可視化機能
- **フレームワーク**: PySide6 を用いた1画面構成。
- **設定パネル**:
  - TCP と RTU の設定を**常時表示**すること。
  - TCP 待受中は TCP 項目のみ、RTU 待受中は RTU 項目のみ非活性（Disabled）にすること。
- **コントロールパネル**:
  - TCP 開始 / 停止ボタン、RTU 開始 / 停止ボタン（それぞれ独立）
  - 接続状態ステータスインジケータ（停止中: 赤 / 動作中: 緑）を TCP / RTU それぞれに表示
  - 各 Slave ID 横に通信状態インジケータ（緑=直近通信 / 灰=待受中未通信 / 薄灰=停止中）
- **データモニター**:
  - 保持レジスタのアドレスと現在値をリストまたはテーブル形式で一覧表示すること。

### F03: データ編集機能
- UI上の入力フィールドから特定の保持レジスタ（例: アドレス `0`）の値を手動で書き換え、内部データストアに即座に反映できること。

### F04: ログ出力機能
- マスタから要求（Read/Write）を受信した際、そのイベント（日時、モード[TCP/RTU]、ファンクションコード、アドレス、値）を画面上のテキストエリアにリアルタイム出力すること。

## 3. 非機能要件・制約事項
- **動作環境**: Python 3.10 以上、クロスプラットフォーム（Windows/Linux）で動作すること。
- **主要ライブラリ**: `pymodbus`（通信）、`pyserial`（RTU通信用依存ライブラリ）、`PySide6`（UI構築）
- **スレッド・非同期制御**: 
  GUIの描画スレッドをフリーズさせないため、Modbus TCP/RTUいずれのリスニングループも `asyncio` を用いてバックグラウンド実行すること。
  （※`pymodbus` の `StartAsyncModbusSerialServer` を使用すること）
