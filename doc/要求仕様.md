# 要求仕様書：Modbus TCP / RTU マルチ模擬ツール（シミュレータ）

## 1. プロジェクト全体の概要

- **システムの目的・背景**:  
  Modbus 通信を行う上位システム（マスタ）の開発やテストにおいて、実機（スレーブ）がない状態でも通信疎通およびデータハンドリングの検証を可能にするため、ローカル環境で動作する軽量な UI を持つ Modbus シミュレータを構築する。
- **ターゲットユーザー**: 通信検証・デバッグを行う開発者
- **主要な機能一覧**:
  1. Modbus TCP / RTU スレーブの同時待受、非同期起動・停止
  2. 経路別（TCP / RTU）のスレーブ・レジスタ可視化
  3. UI からのレジスタ値の動的変更
  4. 外部マスタとの通信ログ（要約 + 生パケット）
- **システムの全体的な流れ**:  
  アプリ起動 → 通信パラメータ設定 → 経路別スレーブ設定 → TCP/RTU 開始 → バックグラウンドで待受 → 外部マスタ要求を処理しつつ UI / ログを更新

---

## 2. 詳細機能要件

### F01: 通信制御機能

- **通信プロトコル**: Modbus TCP および Modbus RTU（**同時起動可能**）
- **ロール**: スレーブ（サーバー）
- **データ分離**: TCP 用スレーブと RTU 用スレーブは**独立**（同じ Slave ID でも別データ）
- **TCP 設定パラメータ**:
  - IP アドレス（候補から選択または入力、IPv4/IPv6）
  - ポート番号（例: `5020`）
  - Linux/WSL では 1024 未満は特権ポートのため UI で拒否。ネイティブ Windows では 502 なども利用可
- **RTU 設定パラメータ**:
  - シリアルポート（検出リストまたは手動入力。未検出時は空欄とし、実在しないポートを仮置きしない）
  - ボーレート（`9600`, `19200`, `38400`, `115200`、デフォルト: `9600`）
  - パリティ（`None`, `Even`, `Odd`、デフォルト: `Even`）
  - データビット（`7` / `8`、デフォルト: `8`）※可変
  - ストップビット（`1` / `2`、デフォルト: `1`）※可変
- **データストア**:
  - Holding Register を主対象。アドレス `0` 〜 `65535`
  - 型: `uint16` / `int16` / `int32`（int32 は 2 レジスタ、Addr ≤ 65534）
  - サーバは**設定済みアドレスのみ**を構築する（疎なマップ）

### F02: 画面 UI・データ可視化機能

- **フレームワーク**: PySide6（1 ウィンドウ）
- **タブ**:
  - 通信設定
  - TCP スレーブ
  - RTU スレーブ
  - 通信ログ
- **設定パネル**: TCP / RTU を常時表示。待受中は該当側のみ Disabled
- **コントロール**: TCP / RTU それぞれの開始・停止と状態インジケータ（停止: 赤 / 待受: 緑）
- **Slave 一覧**: 各 ID 横に通信状態（緑=直近通信 / 灰=待受中未通信 / 薄灰=停止中）

### F03: データ編集機能

- 表内で Addr / Raw / Decoded / Datatype / Tag を編集し、内部データストアに即反映
- Datatype はリスト選択（自由入力による不正値を防ぐ）
- Decoded は 16 進（`0x` あり・なし両方可）。負数も正しく往復できること
- 待受中も値・機器名の編集が可能であること

### F04: ログ出力機能

- 通信時に次をテキストエリアへ出力する:
  - 日時
  - モード（TCP / RTU）
  - 方向（RX / TX）
  - 要約（device / FC / アドレス / 値など）
  - 生パケット（16 進）
- 明らかに不正な TCP フレーム（例: protocol id ≠ 0）は `INVALID` 行として記録する

## 3. 非機能要件・制約事項

- **動作環境**: Python 3.10 以上。Windows / Linux / WSL2
- **主要ライブラリ**: `pymodbus`、`pyserial`、`PySide6`
- **スレッド・非同期**: GUI をブロックしないよう、TCP/RTU 待受は `asyncio` でバックグラウンド実行する
- **設定永続化**: ユーザーホーム配下の `settings.json` に自動保存・復元
- **テスト**: アドレス境界、データ型、通信ログ、TCP、RTU（仮想シリアル）などを自動テストで検証する
